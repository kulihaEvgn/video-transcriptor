# CLAUDE.md

Инструкции для Claude Code в этом проекте. Пользовательская документация — в `README.md`.

## Что это

Видео на входе, markdown с транскриптом и скриншотами на выходе. Раздаётся плагином для Claude Code, внутри — обычный питоновский скрипт.

| Файл | Что это |
| --- | --- |
| `vidnotes.py` | ядро и командная строка |
| `vidnotes_gui.py` | окно на tkinter поверх ядра |
| `skills/vidnotes/SKILL.md` | навык: как Claude пользуется скриптом |
| `.claude-plugin/` | манифесты плагина и маркетплейса |

Зависимости: `pywhispercpp` (whisper.cpp) и `av` (чтение видео и нарезка кадров). tkinter берётся из стандартной библиотеки, Qt не тащить. Новые зависимости добавлять, только если задача правда не решается тем, что уже есть.

## Устройство

Ядро разбито надвое специально — в плагине середину делает сам Claude, а не отдельный процесс:

1. `prepare()` — расшифровка, пишет `transcript.srt` и `.txt`, отдаёт папку и рекомендованное число моментов;
2. **выбор моментов** — в плагине это работа Claude (он читает srt и пишет `moments.txt`), в командной строке — `pick_moments()`, который зовёт внешнего агента, по умолчанию `claude -p`;
3. `assemble()` — режет кадры в `shots/NN_HH-MM-SS.jpg` и собирает markdown.

`run()` склеивает все три шага для командной строки. Флаги `--transcribe-only` и `--moments <файл>` дают доступ к половинкам по отдельности — ими и пользуется навык.

Всё длинное принимает `log=` — колбэк для строки прогресса. CLI передаёт `print`, окно — очередь событий. Ошибки, которые должен увидеть пользователь, кидаются как `VidnotesError`.

Окно держит работу в отдельном потоке, а события гоняет через `queue.Queue`, которую главный поток разбирает по таймеру `after(100)`. Трогать виджеты из рабочего потока нельзя — tkinter этого не переживает.

## Почему так, а не иначе

**Движок — whisper.cpp, а не faster-whisper.** Замерено на 43-минутной записи: pywhispercpp 3:25, faster-whisper 8:20 — потому что первый умеет Metal, а ctranslate2 нет. Плюс вес: 4 МБ против тридцати с лишним (ctranslate2 + токенизатор + numpy + hf_xet) и onnxruntime на 71 МБ в придачу. Раньше в проекте жила отдельная bash-версия ради Metal — с переходом причина исчезла, и она удалена (ищи в истории, если понадобится).

**Звук декодирует `av`, а не системный ffmpeg.** pywhispercpp на любой не-WAV файл зовёт `ffmpeg` из PATH (см. его `_load_audio`) — а у человека, который просто поставил плагин, бинаря нет, и всё падало сырым английским исключением. `read_audio` приводит звук к 16 кГц моно сам и отдаёт whisper.cpp массивом: текст расшифровки совпадает дословно (сверено), временный WAV на 80 МБ не пишется, длительность считается по числу сэмплов. Проверено с `PATH` без ffmpeg — работает.

**Кадры режет `av`, а не бинарь ffmpeg.** `av` и так стоит, внутри него тот же ffmpeg; отдельное колесо `imageio-ffmpeg` было лишними 47 МБ. Кадры совпадают с ffmpeg пиксель в пиксель — проверено на 43-минутной записи, расхождение 0.00 из 255.

**Готовых сборок (.exe/.app) нет.** PyInstaller собирал их нормально, но неподписанное приложение блокируют и Windows, и macOS, а инструкция «отключите защиту» — не то, что раздают коллегам. Подпись стоит денег и требует аккаунтов; плагин обходит вопрос целиком. Если сборки понадобятся снова — workflow лежит в истории.

## Грабли, на которые уже наступали

**Агент отдаёт таймкоды в формате SRT.** Просишь `HH:MM:SS`, а он копирует формат из входного файла и присылает `00:00:08,260` — с миллисекундами через запятую. Регулярка `MOMENT` поэтому принимает опциональные `[.,]ddd`.

**Агент не держит запрошенное число моментов.** Просишь 20 — присылает 30. Список подрезается по `count`.

**Число моментов не спрашиваем у пользователя.** Он не знает заранее, сколько в записи важного, — знает только длительность. Считаем сами: примерно один момент на две минуты, не меньше 5 и не больше 30.

**Подпись и кадр держатся вместе только парами.** `grab_frames` может пропустить момент (таймкод за концом записи, битый участок) и поэтому отдаёт `(момент, имя файла)`, а не список имён: обрезать список моментов «по числу кадров» нельзя — пропуск в середине сдвигает все следующие подписи.

**Кадр за концом видео.** Агент иногда присылает таймкод длиннее записи. `av` в этом случае отдаёт последний декодированный кадр — берём его только если он в двух секундах от нужного, иначе момент пропускаем.

**У webm и mkv из записи экрана нет длительности в контейнере.** `container.duration` там `None` — а от неё считается число моментов, и на любую запись выходило минимальные 5. Длительность берём из звука (`len(audio) / AUDIO_RATE`), не из метаданных.

**Точность кадра ломается молча.** `av` встаёт на ключевой кадр не позже нужной секунды и доходит декодированием. Меняешь это место — повтори сверку с ffmpeg-эталоном, глазами сдвиг на секунду не виден.

**`multiprocessing.freeze_support()` в обеих точках входа.** Нужен, если кто-то снова возьмётся паковать PyInstaller: в собранном виде дочерний процесс перезапускает сам бинарь и прилетает в argparse с флагами интерпретатора. Стоит одной строкой, не мешает.

## Проверки

`python test_vidnotes.py` — проверки без фреймворков и без `av`/`pywhispercpp`: разбор таймкодов, формат времени SRT, счёт моментов, разбор ответа агента (поддельным агентом на `sys.executable`), сборка markdown и перенос результата в выбранную папку (единственное место, где можно потерять чужие файлы).

`grab_frames` и `read_audio` тестами не покрыты — им нужны настоящее видео и `av`; после правок в них гоняй сквозной прогон ниже.

Прогон делай с `PATH` без ffmpeg (`env PATH="$HOME/.local/bin:/usr/bin:/bin"`) — иначе возврат зависимости от системного бинаря не заметишь: у тебя-то он стоит.

Сквозной прогон на тестовом видео, реальная запись не нужна:

```bash
cd "$(mktemp -d)"
say -v Milena -o speech.aiff "Привет. Открываю панель фильтров. \
Договорились: ограничение на строки убираем. Теперь показываю деплой на стенд."
ffmpeg -v error -y -f lavfi -i "testsrc2=s=640x360:d=30" -i speech.aiff \
  -shortest -c:v libx264 -pix_fmt yuv420p -c:a aac test.mp4
uv run --with pywhispercpp --with av ~/code/projects/vidnotes/vidnotes.py test.mp4 ru
```

Смотреть надо на три вещи: транскрипт разборчив, `moments.txt` непустой, число файлов в `shots/` совпадает с числом строк в нём.
