# CLAUDE.md

Инструкции для Claude Code в этом проекте. Пользовательская документация — в `README.md`.

## Что это

Видео на входе, markdown с транскриптом и скриншотами на выходе. Три способа запуска, одна логика:

| Файл | Что это | Кому |
| --- | --- | --- |
| `vidnotes` | bash-скрипт, whisper.cpp на Metal | macOS, самый быстрый путь |
| `vidnotes.py` | ядро + командная строка, faster-whisper на CPU | Windows, Linux |
| `vidnotes_gui.py` | окно на tkinter поверх ядра | коллеги, которым терминал не нужен |

Bash-версия живёт отдельно и специально: на маке она в разы быстрее, потому что whisper.cpp умеет Metal, а ctranslate2 (движок faster-whisper) — нет. Это осознанное дублирование, а не забытый черновик. Правишь поведение — правь обе, интерфейс и состав выходной папки должны совпадать.

Зависимости у python-версии: `faster-whisper`, `imageio-ffmpeg`. tkinter брать из стандартной библиотеки, никаких Qt. Новые зависимости добавлять только если задача правда не решается тем, что уже есть.

## Устройство

Ядро в `vidnotes.py`, функция `run()` — три шага:

1. `transcribe()` — faster-whisper читает видео напрямую (через PyAV, отдельный ffmpeg для этого не нужен), пишет `transcript.srt` и `.txt`;
2. `pick_moments()` — отдаёт транскрипт агенту, забирает строки `HH:MM:SS | подпись` в `moments.txt`, сырой ответ кладёт в `agent.txt`;
3. `grab_frames()` — режет кадры в `shots/NN_HH-MM-SS.jpg` тем же `av`: seek на ключевой кадр не позже нужной секунды, дальше доходим декодированием, кодируем через mjpeg. Отдельный бинарь ffmpeg в python-версии не нужен — он и так лежит внутри `av`, тащить вторую копию колесом `imageio-ffmpeg` было лишними 47 МБ в сборке.

Всё длинное принимает `log=` — колбэк для строки прогресса. CLI передаёт `print`, окно — очередь событий. Ошибки, которые должен увидеть пользователь, кидаются как `VidnotesError`: CLI печатает их без трейсбека, окно показывает в диалоге.

Окно (`vidnotes_gui.py`) держит работу в отдельном потоке, а события гоняет через `queue.Queue`, которую главный поток разбирает по таймеру `after(100)`. Трогать виджеты из рабочего потока нельзя — tkinter этого не переживает.

## Грабли, на которые уже наступали

**Имя модели ≠ имя репозитория.** `large-v3-turbo` лежит в `mobiuslabsgmbh/faster-whisper-large-v3-turbo`, а `small` — в `Systran/faster-whisper-small`. Единого шаблона нет, поэтому `_repo_id()` берёт маппинг `_MODELS` из самой faster-whisper. Собирать имя строкой — как я сначала и сделал — даёт 401 от Hugging Face, который читается как «нет доступа», хотя на деле репозитория просто не существует.

**Агент отдаёт таймкоды в формате SRT.** Просишь `HH:MM:SS`, а он копирует формат из входного файла и присылает `00:00:08,260` — с миллисекундами через запятую. Регулярка `MOMENT` поэтому принимает опциональные `[.,]ddd`, а bash-версия отдельно меняет запятую на точку: `ffmpeg -ss` понимает точку и не понимает запятую.

**Точность кадра — то, что ломается молча.** В bash-версии `-ss` стоит перед `-i`: выглядит как быстрый seek по ключевым кадрам, но современный ffmpeg досекундно точен и в этой позиции. В python-версии тот же результат даёт связка seek + декодирование вперёд. Обе проверены на 43-минутной записи сравнением с эталоном: расхождение 0.00 из 255 на всех таймкодах. Меняешь эти места — повтори замер, глазами такой сдвиг не виден.

**Агент не держит запрошенное число моментов.** Просишь 20 — присылает 30. Поэтому список подрезается по `count` в обеих версиях.

**whisper-cli пишет в stderr простыню** про Metal и размеры буферов — в bash-версии stderr уходит в `whisper.log`. Сегменты речи он печатает в stdout, это оставлено видимым.

**onnxruntime в сборку не кладём.** faster-whisper тянет его только ради отсечения тишины (`vad_filter`), а это 71 МБ из 188 — больше трети веса при том, что сам движок распознавания `ctranslate2` весит 5 МБ. Мы VAD не включаем, поэтому в PyInstaller стоит `--exclude-module onnxruntime`. Включишь `vad_filter=True` — сборка упадёт при первом же вызове; тогда придётся вернуть модуль и смириться с весом.

**Собранную версию проверять запуском, а не глазами.** PyInstaller разрешает импорты в рантайме, поэтому сборка может собраться и упасть на первой же обработке. Так вылез `multiprocessing`: в упакованном виде дочерний процесс перезапускает сам бинарь, прилетает в argparse с флагами интерпретатора `-B -S -I -c` и роняет разбор аргументов, а в окне это грозит вторым окном вместо работы. Лечится `multiprocessing.freeze_support()` первой строкой в обеих точках входа — не убирать.

## Проверки

`python test_vidnotes.py` — три проверки без фреймворков: разбор таймкодов, формат времени SRT и перенос результата в выбранную папку. Последнее — единственное место, где можно потерять чужие файлы, поэтому там проверяется и отказ от перезаписи.

Сквозной прогон на тестовом видео, реальная запись не нужна:

```bash
cd "$(mktemp -d)"
say -v Milena -o speech.aiff "Привет. Открываю панель фильтров. \
Договорились: ограничение на строки убираем. Теперь показываю деплой на стенд."
ffmpeg -v error -y -f lavfi -i "testsrc2=s=640x360:d=30" -i speech.aiff \
  -shortest -c:v libx264 -pix_fmt yuv420p -c:a aac test.mp4
vidnotes test.mp4 ru 2
cat test_notes.md
```

Смотреть надо на три вещи: транскрипт разборчив, `moments.txt` непустой, число файлов в `shots/` совпадает с числом строк в `moments.txt`. Отдельно — что кадр берётся с запрошенной секунды:

```bash
ts=$(head -1 test_notes/moments.txt | cut -d'|' -f1 | tr -d ' ' | tr ',' '.')
ffmpeg -v error -y -i test.mp4 -ss "$ts" -frames:v 1 -q:v 2 ref.jpg
md5 -q ref.jpg test_notes/shots/01_*.jpg   # хеши должны совпасть
```
