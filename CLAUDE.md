# CLAUDE.md

Инструкции для Claude Code в этом проекте. Пользовательская документация — в `README.md`.

## Что это

`vidnotes` — один bash-скрипт (~50 строк) без зависимостей от языков и пакетных менеджеров. Видео на входе, markdown с транскриптом и скриншотами на выходе. Внешние инструменты: `ffmpeg`/`ffprobe`, `whisper-cli` (из `brew install whisper-cpp`), `claude` (Claude Code CLI).

Держим его одним файлом. Разносить на модули, переписывать на python, добавлять конфиг или зависимости — не надо, пока задача не потребует по-настоящему.

## Устройство

Четыре шага, каждый печатает `[N/4]`:

1. `ffmpeg` → `$OUT/audio.wav` (моно 16 кГц — whisper другого не ест);
2. `whisper-cli` → `$OUT/transcript.srt` + `.txt`, stderr уходит в `$OUT/whisper.log`;
3. `claude -p` читает srt со stdin, возвращает строки `HH:MM:SS | подпись`, они фильтруются грепом в `$OUT/moments.txt`;
4. `ffmpeg` режет кадр на каждый таймкод в `$OUT/shots/NN_HH-MM-SS.jpg` — по имени видно и порядок, и момент; тот же таймкод уходит в alt-текст картинки. Всё собирается в `<видео>_notes.md`.

`$OUT` = `<имя видео>_notes/` рядом с исходником. `audio.wav` удаляется в конце, остальное остаётся.

## Грабли, на которые уже наступали

**Claude отдаёт таймкоды в формате SRT.** Просишь `HH:MM:SS`, а он копирует формат из входного файла и присылает `00:00:08,260` — с миллисекундами через запятую. Греп на шаге 3 поэтому принимает опциональные `[.,]ddd`, а в цикле шага 4 запятая меняется на точку: `ffmpeg -ss` понимает точку и не понимает запятую. Не «упрощать» ни то, ни другое — сломается молча: греп отсеет все строки, скрипт упадёт на пустом `moments.txt`.

**`-ss` перед `-i` здесь точный.** Выглядит как быстрый seek по ключевым кадрам, но современный ffmpeg досекундно точен и в этой позиции — проверено сравнением md5 с эталонным `-i ... -ss`. Переставлять `-ss` после `-i` ради «точности» не нужно: станет во много раз медленнее на длинных записях, кадр тот же.

**Claude не держит запрошенное число моментов.** Просишь 20 — присылает 30. Поэтому список подрезается `head -n "$COUNT"` после грепа: так число кадров всегда совпадает с тем, что просили. Убирать подрезку нельзя, иначе аргумент превращается в пожелание.

**whisper-cli пишет в stderr простыню** про Metal, размеры буферов и тайминги — поэтому stderr в лог-файл. Сегменты речи он печатает в stdout, это оставлено видимым: по ним видно, что процесс идёт.

## Как проверять правки

Реальное видео не нужно, тестовое собирается из системного TTS и генератора картинки:

```bash
cd "$(mktemp -d)"
say -v Milena -o speech.aiff "Привет. Открываю панель фильтров. \
Договорились: ограничение на строки убираем. Теперь показываю деплой на стенд."
ffmpeg -v error -y -f lavfi -i "testsrc2=s=640x360:d=30" -i speech.aiff \
  -shortest -c:v libx264 -pix_fmt yuv420p -c:a aac test.mp4
vidnotes test.mp4 ru 2
cat test_notes.md
```

Прогон занимает секунд десять. Смотреть надо на три вещи: транскрипт разборчив, `moments.txt` непустой, число файлов в `shots/` совпадает с числом строк в `moments.txt`.

Отдельно стоит убедиться, что кадр берётся именно с запрошенной секунды:

```bash
ts=$(head -1 test_notes/moments.txt | cut -d'|' -f1 | tr -d ' ' | tr ',' '.')
ffmpeg -v error -y -i test.mp4 -ss "$ts" -frames:v 1 -q:v 2 ref.jpg
md5 -q ref.jpg test_notes/shots/01.jpg   # хеши должны совпасть
```
